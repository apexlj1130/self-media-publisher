# 小红书浏览器发布流程

## 安全路线

只使用用户可见的真实 Chrome 和小红书创作服务平台正常 UI。优先使用专用于发布的小红书 Chrome Profile，以降低扩展冲突和账号环境漂移；不强制迁移已有登录态。

明确禁止：

- 私有或逆向发帖 API；
- 导出 Cookie、读取 xsec token 或复用浏览器内部认证材料；
- Headless 浏览器、CDP 远程调试、Debugger 权限；
- 页面脚本注入、模拟发布事件、Shadow DOM 穿透；
- UA/Canvas/指纹伪装、验证码识别或风控绕过；
- 安装需要 `cookies`、`debugger`、`scripting`、`webRequest` 等高权限的发布扩展。

浏览器或系统安全策略拒绝时完全停止，不切换工具绕过。

## 登录与挑战

1. 打开小红书创作服务平台，观察当前登录状态和账号身份。
2. 已登录时核对显示账号与当前单账号配置一致。
3. 扫码、短信、验证码、实名、设备确认、风险提示或重新登录出现时，停止操作并通知用户接管。
4. 用户处理后重新观察当前页面继续，不刷新或清空刚完成的验证。

不读取、保存或代填密码、验证码、Cookie。

## 填充图文笔记

1. 在外部写入前再次运行 `validate_xhs_package.py`，记录当前 `fingerprint`。
2. 打开图文发布入口，按包内 `images` 顺序上传图片；等待所有图片完成处理。
3. 逐张观察页面缩略图，核对顺序、重复、裁切、乱码和关键信息。页面实际顺序与包不符时用正常 UI 调整。
4. 填写标题和正文。不要把 `#` 前缀写入标签字段；标签通过页面正常标签 UI 添加。
5. 设置包中指定的可见范围和原创选项；未在包中指定的设置保持页面默认。
6. 检查页面字数、图片数量或提示是否比离线校验更严格。若页面要求修改，回写包、重新计算指纹并重新填充。

## 预览与确认

填充完成不等于可以发布。使用页面提供的预览能力，至少核对：

- 封面在首图且主体位于安全区域；
- 图片顺序形成完整叙事，无重复和上传失败；
- 标题没有截断；正文段落和表情不过度；
- 标签有效且没有把正文尾部文本误识别为标签；
- 可见范围和原创选项与发布包一致；
- 页面没有风险警告、侵权提示或待确认弹窗。

向用户报告当前标题、图片数、标签、指纹和异常，停在发布按钮之前。用户确认必须明确指向当前小红书版本。

## 发布与结果核对

1. 确认后若页面或包发生变化，旧确认立即失效，重新预览。
2. 有效确认后只点击一次发布。
3. 等待明确成功页面、作品管理记录或草稿状态变化。
4. 超时、空白或结果不明时不重复点击。先用正常 UI 查看作品管理和草稿；仍无法确认就报告状态未知并停止。
