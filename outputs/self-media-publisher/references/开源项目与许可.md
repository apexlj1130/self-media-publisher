# 开源项目与许可

本 Skill 没有把上游仓库整体复制进来。它提炼已验证的接口边界和交互原则，并以测试先行方式重写最小实现。

## 微信公众号

- 项目：[`jiji262/wechat-publisher`](https://github.com/jiji262/wechat-publisher)
- 使用方式：参考官方 API 的 token、永久封面素材、正文图片、`draft/add`、有限重试和移动端列表问题经验。
- 复用边界：本 Skill 自行实现最小 API 适配器，不复用上游生图后端、评分器、多平台同步、常驻服务或运行配置。
- 许可：上游 README 声明 MIT；评估快照未发现独立 `LICENSE` 文件，因此只作为设计来源记录，不复制其大段源码或许可不明资产。

- 项目：[`sakuraoxo/wechat-publisher`](https://github.com/sakuraoxo/wechat-publisher)
- 使用方式：参考 Markdown 到公众号草稿的 Skill 组织方式。
- 许可：MIT。

## 小红书

- 项目：[`autoclaw-cc/xiaohongshu-skills`](https://github.com/autoclaw-cc/xiaohongshu-skills)
- 使用方式：参考“先填充和预览，再单独点击发布”的人机协作流程。
- 未采用部分：Chrome Bridge 及其 `cookies`、`debugger`、`scripting`、`webRequest` 权限，本 Skill 不安装、不复制、不连接该扩展。
- 许可：MIT。

- 项目：[`tensorslab/xhs-skills`](https://github.com/tensorslab/xhs-skills)
- 使用方式：只参考把长文重构成多张小红书内容图的叙事思路。
- 未采用部分：HTML/CSS 卡片渲染与 CDP 发布。用户要求全部图片由 Codex AI 生图，因此程序化卡片不进入本 Skill。

## 修改说明

- 统一内容包和媒体清单是本项目新增契约。
- 微信适配器只保留单账号普通图文草稿，增加配置权限检查、私有 token 缓存、非幂等写入不重试和草稿回读。
- 小红书发布底座改为 Codex 可见 Chrome Computer Use，明确禁止私有 API、Cookie、CDP、脚本注入和指纹绕过。
- 两个平台共用来源治理，但确认、发布和结果状态相互独立。
