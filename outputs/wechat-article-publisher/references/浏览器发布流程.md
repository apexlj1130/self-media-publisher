# 微信公众号浏览器发布流程

## 适用边界

本流程只适用于微信公众号官方后台 `mp.weixin.qq.com` 的单篇普通图文。页面文案和结构可能变化，因此每次都先观察当前 Chrome 标签页，再依据可访问性角色、名称、可见文字和截图定位。

如果用户指定了 Chrome 或某个标签页，使用该表面。否则使用当前 Chrome 配置打开官方后台。不要把坐标、临时元素 ID 或某次页面层级写成长期规则。

## 登录与人工接管

1. 观察页面，判断已登录、扫码登录、账号选择或安全验证状态。
2. 已登录时核对后台展示的公众号身份是否与用户当前任务一致。
3. 出现二维码、短信、验证码、安全确认、账号选择或原创资格异常时，停止自动操作并通知用户处理。
4. 用户完成后重新观察页面，从当前状态继续；不要重复导航或清空用户刚完成的验证。

不读取、保存、代填密码或验证码，不尝试规避风控。

## 高效转入正文

1. 在独立 Chrome 标签页打开 `article-staging.html`。本地文件 URL 不可用时，可在运行目录启动仅绑定本机的临时 HTTP 服务；使用服务实际输出的可用端口。
2. 复制暂存稿文章容器中的正文，不复制页面背景或浏览器装饰。
3. 在公众号后台创建普通单篇图文草稿，标题单独填入标题字段；正文不重复一级标题。
4. 将富文本粘贴到原生编辑器。粘贴后立即检查标题层级、段落、引用、列表、代码样式和链接是否被平台保留。
5. 平台剥离了必要样式时，在原生编辑器中重新应用；实际渲染优先于暂存 HTML。

## 插入图片与纠偏

1. 依据图片 ID 建立本地文件映射；封面 `image-01` 单独设置，不在正文重复插入，除非用户明确要求。
2. 对每张正文图寻找对应占位标记，并结合 `position_text`、作用、章节内容判断真正插入点。
3. 上传图片后删除占位标记，重新检查图片前后的段落和章节边界。
4. `review_within_section` 必须人工式复核。例如“讲完三个问题、进入优化方案之前”应放在问题描述结束、优化段落开始之前，而不是机械地放在章节末尾。
5. 图片顺序、数量或语义不一致时现场移动或重新上传。脚本锚点没有否决页面纠偏的权力。

## 封面、原创和预览

1. 设置 AI 生成的封面，检查 2.35:1 裁切、安全区域、标题文字和核心图形。
2. 默认开启原创声明。若平台弹出额外承诺、资质或可能改变用户权利的选项，暂停交给用户处理。
3. 其他发布选项沿用后台默认值，不主动修改。
4. 保存草稿，使用平台原生预览，从头到尾完成复核。
5. 停留在预览或草稿状态，向用户请求当前草稿的明确发布确认。

## 发布与结果核对

1. 有效确认必须发生在当前预览之后，并绑定当前标题、正文、图片、封面和发布设置。
2. 最终复核发现需要改动时，完成改动、重新预览，并重新请求确认。
3. 有有效确认后点击一次发布。平台出现二次安全确认时由用户接管。
4. 等待明确结果。若超时、页面空白或状态不明，先查看成功提示、已发表列表和草稿状态。
5. 只有权威页面证明未发布且当前操作可以安全重试时，才考虑再次操作；否则停止并报告不确定状态。
