# 微信公众号文章发布 Skill 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. The user explicitly requires inline execution by the main Agent; do not use subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 创建、验证并安装个人 Codex Skill `wechat-article-publisher`，使其能够解析约定格式的长文、组织全 AI 配图、通过 Chrome Computer Use 完成排版与复核，并只在当前文章获得明确确认后发布。

**Architecture:** 使用一个 Codex 原生 Agent Loop 负责编排和语义判断；无依赖 Python 准备器负责确定性解析、语义锚点候选和微信兼容暂存 HTML；AI 生图工具负责全部图片；Chrome Computer Use 负责真实页面操作与纠偏；用户确认和平台结果构成发布副作用闸门。不引入 LangChain、LangGraph 或 Deep Agents，因为首版没有独立并行目标、跨会话持久状态或自定义图恢复需求。

**Tech Stack:** Codex Skills、Python 3.9 标准库、`unittest`、Chrome Computer Use、AI image generation、Git、GitHub CLI。

**Spec:** `docs/product/需求规格.md`、`docs/功能设计.md`、`docs/技术架构设计.md`

## 全局约束

- 所有工作由主 Agent 完成，不使用子代理。
- 首版只支持单账号、单篇普通图文文章。
- 所有封面和正文图均由 AI 生图工具生成；程序化 HTML 只用于正文排版暂存，不用于绘制配图。
- 脚本只生成候选结构和样式；微信编辑器内的真实页面由 Computer Use 复核并纠偏。
- 登录、安全验证、原创资格异常由用户处理。
- 当前文章没有明确“确认发布”时，不得发布。
- 离线验收不得登录公众号、创建草稿或触发真实发布。
- 使用缩减版企业交付门禁：验证公开命令、输入输出、失败路径、安装包身份和干净目录安装；角色、数据库、升级迁移矩阵不适用。
- 远程交付使用已登录 GitHub 账号 `apexlj1130`。目标仓库不存在时，创建私有仓库 `apexlj1130/wechat-article-publisher`，避免未经确认公开文章与测试样例。

### Task 2：实现无依赖文章准备器

**Files:**
- Create: `outputs/wechat-article-publisher/scripts/prepare_article.py`
- Modify: `outputs/wechat-article-publisher/tests/test_prepare_article.py`

**Interfaces:**
- Consumes: UTF-8 Markdown 文件。
- Produces: `ParseError`、`parse_article`、`render_staging_html`、`write_package` 和 CLI `main`；输出稳定的 JSON 与 HTML 文件。

- [x] **Step 1：实现最小解析数据结构**

Implement `ParseError(ValueError)` and parsing helpers using only Python 3.9 standard library. The returned mapping must contain:

```python
{
    "schema_version": 1,
    "source_sha256": "<64 lowercase hex characters>",
    "title": str,
    "body_markdown": str,
    "headings": [{"index": int, "level": int, "text": str}],
    "images": [{
        "id": "image-01",
        "number": 1,
        "kind": "cover" | "inline",
        "position_text": str,
        "purpose": str,
        "aspect_ratio": str,
        "prompt": str,
        "anchor": {
            "heading_index": Optional[int],
            "heading_text": Optional[str],
            "placement": "cover" | "after_section" | "review_within_section"
        }
    }],
    "layout_instructions": [str],
    "publish_options": {"declare_original": True}
}
```

Image numbers must be unique and contiguous from 1. Missing required blocks raise `ParseError` with a field-specific Chinese message.

- [x] **Step 2：实现语义锚点候选**

Map “正文最前面” to `cover`; match explicit Chinese chapter numbers in `position_text` to parsed level-2 headings; use `after_section` for “章节结束后/章节之后”; use `review_within_section` for “进入……之前” or other within-section wording. Preserve the complete `position_text` so Computer Use can override the candidate.

- [x] **Step 3：实现安全的 Markdown 子集渲染**

Escape raw HTML first, then render headings, paragraphs, blockquotes, ordered/unordered lists, horizontal rules, strong text, inline code, and Markdown links. Use inline styles matching the approved template. Exclude the source H1 and append visible image markers carrying `data-image-id`. Every ambiguous marker must display “需按语义复核位置”。

- [x] **Step 4：实现文件输出和 CLI**
