# 自媒体双平台发布 Skill 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. The user explicitly requires inline execution by the main Agent; do not use subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把现有 `wechat-article-publisher` 升级为 `self-media-publisher`，默认同时准备微信公众号和小红书，使用微信官方 API 创建可回读草稿，并通过安全的可见 Chrome 流程填充和复核小红书。

**Architecture:** 使用单一 Codex Agent Loop 编排。Python 标准库负责统一内容解析、运行包校验和微信 HTML；最小 `requests`/PyYAML 适配器负责微信官方 API；小红书只由 Computer Use 操作可见 Chrome。两个平台共享原始来源和媒体资产治理，但拥有独立内容、指纹、草稿和确认闸门。

**Tech Stack:** Codex Skills、Python 3.9+、`unittest`、`requests`、PyYAML、微信公众平台官方 API、Codex `imagegen`、Chrome Computer Use、Git。

**Spec:** `docs/product/需求规格.md`、`docs/功能设计.md`、`docs/技术架构设计.md`

## 全局约束

- 主 Agent 内联执行，不使用子代理。
- 默认平台严格为 `wechat`、`xiaohongshu`；用户当次可明确缩小范围。
- 全部图片使用 Codex `imagegen`，程序不生成图片。
- 微信配置、token、真实文章和运行产物不得进入 Skill 包或 Git。
- 小红书不得使用私有 API、Cookie、Headless、CDP、脚本注入、Shadow DOM 穿透或指纹伪装。
- 微信 API 草稿与小红书浏览器草稿都属于真实外部写入，需要单独授权后才做在线验收。
- 正式发布需要当前平台内容版本的明确确认；开发验收不执行正式发布。
- 使用缩减版交付门禁：验证所有公开命令、输入输出、错误路径、精确归档和干净安装副本。
