# 微信公众号文章发布 Skill 功能设计

修订日期：2026-09-16

## 1. 产品定位

`wechat-article-publisher` 是一个个人 Codex Skill。它接收带配图说明的公众号长文，组织 AI 生图、富文本排版、Chrome Computer Use 操作和人工确认，将文章整理为可发布状态，并在用户当次明确确认后完成发布。

首版服务单账号、单篇普通图文文章。

## 2. 输入格式

Skill 识别以下语义结构：

1. 第一个 `#` 标题是公众号标题。
2. 标题后的内容是正文，直到 `# 配图与插图建议`。
3. 每个 `## 配图 N` 块包含位置、作用、尺寸建议和提示词。
4. `## 给 Codex 的发布与排版要求` 是当篇发布指令，优先于默认样式。

图片位置必须解析为语义锚点，例如“第一章节结束后”或“讲完三个问题、进入优化方案之前”，不能只记录易漂移的字符或行号。

## 3. 默认样式

默认样式为“专业技术长文”：

- 标题仅进入公众号标题栏，正文不重复一级标题。
- 正文使用微信兼容字体，约 15–16px、深灰色、1.75–1.9 倍行距。
- 段落保持自然篇幅，不机械地一句一段。
- 二级标题使用深蓝色、加粗和明显上下留白；三级标题较正文略强。
- 保留原稿重点，只少量补充加粗，不整段加粗。
- 引用块使用浅灰蓝背景或左侧细色条。
- 列表紧凑对齐；技术词保留英文；反引号内容使用轻量代码样式。
- 正文图片居中、宽度统一，并紧跟相应观点。
- 章节主要使用留白建立节奏，仅在语义转换需要时保留分隔线。
- 封面按约 2.35:1 检查安全区域和裁切效果。
- 外部引用尽量保留；平台不支持链接形式时保留来源名称，并将地址整理到文末参考资料区。

当篇发布与排版要求可以覆盖这些默认值。

## 4. 用户流程

### 4.1 内容准备

1. 读取原稿并解析标题、正文、配图和排版要求。
2. 展示或记录结构化任务清单，检查缺失、重复和歧义。
3. 为正文生成带基础样式和图片占位标记的富文本暂存稿。

### 4.2 图片生成

1. 按配图编号逐张调用 AI 生图工具。
2. 封面使用提示词要求的比例；正文图遵守各自尺寸建议。
3. 逐张检查主题、构图、中文、数值、流程方向和比例。
4. 发现乱码、内容错误或比例不合格时定向重新生成。
5. 无法获得可发布结果时停止，不把不合格图片带入草稿。

### 4.3 浏览器排版

1. 通过用户指定或当前 Chrome 会话进入微信公众号官方后台。
2. 登录验证需要用户时暂停；验证完成后从当前页面继续。
3. 新建普通图文草稿，填写标题并放入富文本正文。
4. 依据语义锚点插入图片；脚本建议与真实阅读逻辑冲突时，由 Computer Use 现场纠偏。
5. 设置封面，检查裁切和安全区域。

### 4.4 预览复核

Computer Use 必须从头到尾检查：

- 标题、章节和正文是否完整；
- 段落密度、加粗、引用、列表和留白是否合理；
- 图片数量、顺序、位置和中文字是否正确；
- 封面裁切是否完整；
- 原创声明和后台默认项是否符合要求。

复核后保存草稿并停留在预览状态，让用户检查。

### 4.5 发布

1. 等待当前文章的明确“确认发布”。
2. 再次检查标题、封面、正文、图片、原创声明和草稿身份。
3. 确认后的内容若发生变化，重新请求确认。
4. 点击发布；出现额外安全确认时由用户处理。
5. 页面响应不明时先检查发布状态，防止重复发布。

## 5. 异常处理

- 输入结构缺失：指出缺少的块并停止进入浏览器。
- 图片提示词或位置含糊：结合正文与“作用”推断；影响较大时向用户确认。
- 登录失效或安全验证：暂停并通知用户。
- 编辑器粘贴样式丢失：以编辑器真实呈现为准重新应用必要样式。
- 图片上传失败：核对格式、大小和页面状态后有限重试；状态不明时停止重复操作。
- 原创声明异常：暂停交由用户决定。
- 发布结果不明：检查已发表和草稿状态，不重复点击。
