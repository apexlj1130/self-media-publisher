# 自媒体双平台发布 Skill 功能设计

修订日期：2026-09-17

## 1. 产品定位

`self-media-publisher` 是个人 Codex Skill。它把一份原始长文默认改编为微信公众号长文和小红书图文笔记，统一组织 AI 生图、平台草稿、真实页面复核与发布确认。

统一的是入口、素材和确认模型；两个平台的内容表达、草稿身份和最终发布仍然独立。

## 2. 输入与输出

输入沿用现有文章约定：

1. 第一个一级标题为原始标题。
2. 标题后至“配图与插图建议”为正文。
3. 每个“配图 N”块包含位置、作用、尺寸和提示词。
4. “给 Codex 的发布与排版要求”覆盖默认规则。

一次运行输出：

```text
run/
├── content-package.json
├── media-manifest.json
├── wechat/
│   ├── article-staging.html
│   └── draft-result.json
└── xiaohongshu/
    ├── note-package.json
    └── browser-review.json
```

运行目录属于当前任务，不写入 Skill 安装目录。

## 3. 默认双平台流程

### 3.1 内容准备

1. 解析原稿，生成统一内容包和微信暂存稿。
2. 默认目标平台为公众号和小红书；当次明确指定单平台时只准备该平台。
3. 主 Agent 根据原稿语义撰写小红书版本，而不是由脚本机械摘要。
4. 小红书版本包含不超过当前页面限制的标题、自然正文、标签和图片叙事顺序。

### 3.2 图片生成

1. 微信封面与正文图按原始配图任务生成。
2. 小红书单独生成 3:4 封面和内容图；可以复用视觉概念，但不得简单裁切微信横图替代。
3. 每张图使用 Codex `imagegen`，并逐张检查比例、中文、数字和语义。
4. 通过检查后把绝对路径写入 `media-manifest.json`；校验失败则停止进入平台草稿。

### 3.3 微信公众号草稿

1. 从权限受限配置读取单账号 AppID、AppSecret 和作者名。
2. 上传封面和正文图片，生成仅含微信 CDN 图片地址的最终 HTML。
3. 调用官方 `draft/add` 创建草稿。
4. 使用草稿读取接口核对标题、图片数量和正文关键结构。
5. API 草稿只是可复核状态，不代表已发表。

### 3.4 小红书草稿

1. 校验 `note-package.json` 和图片文件。
2. 使用专用可见 Chrome Profile 打开官方创作者页面。
3. 登录失效时由用户扫码或验证。
4. Computer Use 按正常用户操作上传图片、填写标题正文与标签，设置原创选项；其他设置沿用页面默认值。
5. 保存草稿或停在发布前页面，不点击发布。

### 3.5 双平台复核

主 Agent 分别核对：

- 微信：移动端列表、段落、图片位置、封面、原创声明、草稿回读。
- 小红书：封面首图、图片顺序、3:4 裁切、标题、正文、标签、原创选项和可见范围。
- 两个平台内容都与同一原稿一致，但符合各自阅读方式。

向用户报告两个草稿的标题、内容指纹、图片数量和当前状态。

### 3.6 发布

用户可以说“确认发布公众号和小红书”，也可以只确认其中一个平台。确认必须对应当前显示的内容版本。

- 小红书：确认后由 Computer Use 再次复核并可见地点击一次发布。
- 微信：确认后使用平台允许的官方后台操作完成发表；如果 Browser Use 安全策略拒绝，则停下让用户手动点击，不改用其他自动化绕过。

发布结果不明确时先查状态，禁止试探性重复提交。

## 4. 默认样式

微信公众号保持已批准的专业技术长文样式：16px 左右正文、1.8 行高、深蓝标题、克制引用和代码样式、移动端安全列表、统一图片宽度和约 2.35:1 封面。

小红书采用专业、克制、易扫读的知识图文风格：

- 3:4 图片为主；封面表达一个清晰主题。
- 每张内容图只承载一个主要观点，避免密集小字。
- 正文补充准确细节，图片不替代完整事实。
- 不使用夸张标题、引流话术、批量模板腔或站外联系方式。

## 5. 异常处理

- 微信 API `40164`：报告当前出口 IP 白名单问题，不重试。
- 微信图片或草稿响应不明确：读取草稿状态；不能证明成功时停止。
- 小红书登录、安全验证、风险提示：立即暂停交给用户。
- 页面结构变化：重新观察；不能可靠确认控件时停止。
- 图片不合格：重新生图；不得改用程序化卡片规避。
- 任一平台内容变化：只使该平台确认失效，不影响另一个未变化的平台。
