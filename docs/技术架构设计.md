# 微信公众号文章发布 Skill 技术架构设计

修订日期：2026-09-16

## 1. 架构原则

Skill 使用“确定性准备 + AI 图片生成 + 语义化 Computer Use + 人工发布闸门”的混合架构。

确定性脚本负责可验证的解析和样式准备；模型负责语义判断、图片质量和页面纠偏；平台账号验证与最终发布授权由用户负责。脚本输出是建议，不是对真实页面的权威判断。

## 2. 交付结构

```text
wechat-article-publisher/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── scripts/
│   └── prepare_article.py
├── references/
│   ├── 浏览器发布流程.md
│   └── 发布前复核清单.md
└── tests/
    ├── fixtures/
    │   └── 示例文章.md
    └── test_prepare_article.py
```

不添加与执行无关的 README、变更日志或示例占位文件。

## 3. 模块边界

### 3.1 Skill 编排层

`SKILL.md` 负责选择工具、串联流程、声明安全边界和路由到按需参考文件。它不复制浏览器细节或完整检查清单。

### 3.2 文章准备器

`prepare_article.py` 接收 Markdown 文件，输出：

- `article-package.json`：标题、正文边界、配图任务、语义锚点、排版覆盖项和发布默认值；
- `article-staging.html`：适合在 Chrome 中打开和复制的微信兼容富文本暂存稿；
- 图片占位标记：稳定关联配图编号，但不决定编辑器内的最终位置。

准备器不得读取账号信息、打开浏览器、调用生图或触发发布。

### 3.3 AI 图片生成层

通过可用的 AI 生图工具逐张生成封面和正文图。每张图片使用独立 ID 与文章包关联，并由模型视觉检查。图片内容本身不得由程序化 SVG、HTML 画布或模板绘制替代。

### 3.4 Chrome Computer Use 层

浏览器层使用当前 Chrome 用户配置和官方微信公众号后台。定位依据优先级为：可访问性角色与名称、可见文字、结构上下文、截图视觉位置。固定坐标只能用于当前观察后的单次点击，不能成为可复用流程的主要定位方式。

基础样式通过暂存 HTML 提高录入效率；粘贴到微信编辑器后，以实际渲染结果为准。Computer Use 必须重新检查并调整标题层级、段落、图片锚点、封面裁切和发布选项。

### 3.5 确认闸门

确认状态仅绑定当前文章指纹、当前草稿和当前任务。任何正文、图片、封面或发布设置变化都会使确认失效。发布动作必须在有效确认之后执行。

## 4. 核心数据契约

文章包的最小逻辑结构：

```json
{
  "title": "文章标题",
  "body_markdown": "正文",
  "images": [
    {
      "id": "image-01",
      "kind": "cover",
      "position_text": "正文最前面",
      "anchor": {"heading": null, "placement": "cover"},
      "aspect_ratio": "2.35:1",
      "prompt": "生图提示词"
    }
  ],
  "layout_instructions": ["当篇排版要求"],
  "publish_options": {"declare_original": true}
}
```

字段只保留后续步骤不能安全重建的事实。浏览器坐标、页面瞬时控件状态和派生完成标志不写入长期状态。

## 5. 状态与幂等性

运行时跟踪文章内容指纹、图片文件映射、当前草稿标识、已观察的页面状态和用户确认所绑定的版本。发布前重新读取当前草稿关键信息并与确认版本核对。

发布按钮点击后先等待平台结果；超时或页面异常时，通过已发表列表、草稿状态或明确成功提示确认结果。未经状态核对不得再次点击。

## 6. 安全与权限

- 只访问完成任务所需的微信公众号官方页面。
- 不保存账号密码、验证码、Cookie 或会话数据。
- 扫码、验证码、安全确认和原创资格异常由用户处理。
- 生成图片、文章正文和运行包存放于当前任务工作目录，不进入 Skill 安装包。
- 离线测试不访问真实账号；真实草稿验收需要额外明确授权。

## 7. 验证策略

1. 先为准备器编写失败测试，证明样例解析和异常检测尚未实现。
2. 实现最小解析与暂存 HTML 生成逻辑，使聚焦测试通过。
3. 运行样例离线演练，人工核对标题、正文、五张配图、锚点和样式。
4. 使用 Skill 快速校验器检查命名、frontmatter、引用和占位符。
5. 由主 Agent执行压力场景审查，验证登录接管、发布确认、内容变更后重新确认和防重复发布规则。
6. 若用户另行授权，再在真实公众号中仅创建和预览草稿，不发布。

## 8. Agent 能力所有权

| 关注点 | 权威所有者 | 承载方式 | 原因 | 拒绝的重叠 |
|---|---|---|---|---|
| 规划 | 当前主 Agent | Codex 原生任务循环 | 工作流需要根据图片质量和页面观察动态调整 | 不增加第二规划器或子代理 |
| 短期状态 | 当前任务 | 工具结果、文章包和当前页面观察 | 只保留恢复当前发布流程所需事实 | 不建立独立状态数据库 |
| 长期记忆 | 无 | 不适用 | 账号偏好已固化为 Skill 默认规则，文章内容不应跨任务留存 | 不保存文章、Cookie 或账号数据 |
| 运行身份与权限 | Codex/Chrome 运行时及用户 | 当前 Chrome 配置、用户当次发布确认 | 身份和授权不能由模型自行声明 | 不把模型输出当作权限证明 |
| 当前对话与请求 | 当前 Codex 任务 | 用户消息与附件 | 当前文章和确认必须来自本任务 | 不把历史文章或旧确认当成当前输入 |
| 工具安全 | Skill 规则与平台验证 | 只读观察、登录接管、发布确认和防重复点击 | 这些是可客观判断的副作用边界 | 不让模型自行绕过验证码或重复发布 |
| 语义判断 | 当前主 Agent | 原稿、图片和微信页面的可见证据 | 图片质量、锚点和排版需要语言与视觉判断 | 不用脚本分数替代语义复核 |
| 完成判定 | 当前主 Agent，受用户确认与平台结果约束 | 预览复核、明确确认、发布结果 | 模型判断草稿质量；用户授权发布；平台证明提交结果 | 不用布尔字段自证发布成功 |
| 编排 | 单一 Codex Agent Loop | Skill + 本地准备器 + AI 生图 + Computer Use | 一个执行者足以完成顺序工作并处理页面变化 | 不使用 LangGraph、Deep Agents 或自定义图 |
| 评估 | 确定性测试、视觉证据和用户预览 | 单元测试、Skill 校验、截图/页面观察、用户确认 | 同模型自评不是独立证据 | 不以结构化输出或自报置信度作为验收 |

最简单但被拒绝的架构是“只有一份操作提示词”：它无法稳定解析长文、生成可复查的配图清单或提供确定性的输入错误证据。更复杂的 LangChain/LangGraph/Deep Agents 方案也被拒绝，因为首版没有跨会话恢复、并行工作单元或多角色协作需求；Codex 原生单 Agent Loop 已提供模型调用、工具选择、Computer Use 和人工消息交互。

语义停止由当前主 Agent 判断；仍可阻止完成的客观不变量只有：输入包无效、图片未通过检查、登录验证未完成、当前草稿尚未得到明确发布确认、发布结果未被平台状态证明。Skill 不使用任意调用次数作为“完成”条件，资源或工具失败必须报告为未完成。

## 9. 实现后架构复核

复核日期：2026-09-16

- 实现仍为单一 Codex Agent Loop，没有引入 LangGraph、Deep Agents、子代理或第二规划器。
- 准备器只解析输入、生成候选锚点和暂存 HTML；它不调用生图、浏览器或发布动作。
- 图片质量、锚点纠偏和排版完整性由模型结合真实工具结果判断；结构化文章包没有被当作语义正确性的自证。
- 当前任务只持有文章包、图片映射和页面观察；没有新增数据库、跨任务记忆或派生生命周期标志。
- 登录验证、当前草稿确认和发布结果仍是客观副作用闸门；没有工具自由文本可以绕过它们。
- 浏览器参考不保存固定坐标、元素 ID、密码、验证码、Cookie 或会话数据。
- 首轮候选把真实用户文章放入测试夹具，违反数据生命周期边界；现已改为合成夹具，并新增制品隐私回归测试。真实样例只在临时目录验收。
- `simplify` 主 Agent 审查未发现需要重构的重复模块或浅层包装；维持一个深模块 `prepare_article.py` 比拆成多个仅转发文件更清晰。
- 由于用户禁止子代理，代码审查为主 Agent 自审，不属于独立评估。自动化测试、官方 Skill 校验、精确制品复验和用户后续真实预览仍提供互补证据。

实现与已批准架构无功能偏离；只有测试数据生命周期得到收紧。
