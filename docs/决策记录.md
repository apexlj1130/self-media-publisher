# 决策记录

修订日期：2026-09-17

## ADR-001 统一入口、分平台适配

状态：已确认

决定：把原 `wechat-article-publisher` 升级为 `self-media-publisher`。默认同时准备公众号和小红书，但内容包、草稿、确认和发布结果分别管理。

## ADR-002 微信使用官方 API 创建草稿

状态：已确认

决定：沿用 `jiji262/wechat-publisher` 已验证的官方 API 路线和移动端列表经验，在自有 Skill 中重新实现最小、可测试的单账号适配器。API 默认终点是草稿箱，不自动群发。

## ADR-003 小红书采用安全精简 Computer Use 路线

状态：已确认

决定：借鉴 `autoclaw-cc/xiaohongshu-skills` 的分步预览思想，不安装其高权限扩展，不使用 MCP、私有 API、Cookie、CDP、指纹伪装或脚本事件；由 Codex Computer Use 操作可见 Chrome。

## ADR-004 图片全部由 Codex AI 生图

状态：已确认

决定：两个平台的封面和正文图都使用 `imagegen`，不采用上游项目的 HTML/CSS 卡片渲染或外部 Gemini/OpenAI 图片脚本。

## ADR-005 脚本不拥有内容与排版权

状态：已确认

决定：脚本负责结构、校验、微信 API 和候选样式；小红书改编、图片质量与真实页面纠偏由主 Agent 负责。

## ADR-006 分平台确认

状态：已确认

决定：用户可以一次同时确认两个平台，但授权必须明确列出公众号和小红书并绑定各自当前指纹。任一平台内容变化只使该平台确认失效。

## ADR-007 浏览器安全拒绝是硬停止

状态：已确认

决定：Computer Use 或平台安全策略拒绝动作时停止。不得通过 CDP、其他自动化、脚本注入或间接执行绕过。

## ADR-008 单 Agent 与最小状态

状态：已确认

决定：只使用当前主 Agent 和 Codex 原生 Agent Loop。状态保存在当前运行包、工具结果和页面观察中，不引入数据库、子代理或自定义图。

## ADR-009 用户数据和凭证不进入制品

状态：已确认

决定：测试只使用合成内容。凭证、token、Cookie、用户文章、生成图片和草稿收据均不写入 Git 或 Skill 安装包。
