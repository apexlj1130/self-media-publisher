# 决策记录

修订日期：2026-09-16

## ADR-001 使用 Skill 与辅助脚本混合方案

状态：已确认

决定：使用 Skill 负责语义编排和浏览器操作，使用小型本地脚本负责文章解析、语义锚点和富文本暂存稿。

原因：纯指令方式对长文和多图位置不够稳定；全自动浏览器脚本容易受微信公众号页面变化与验证流程影响。

## ADR-002 图片全部由 AI 生图

状态：已确认

决定：封面和正文信息图全部由 AI 生图工具生成，不使用程序化图形替代。

影响：中文清晰度和信息准确性需要逐图视觉检查；无法达到可发布质量时停止流程。

## ADR-003 脚本不拥有最终排版权

状态：已确认

决定：脚本生成候选位置和样式，Computer Use 依据微信编辑器真实页面复核并纠偏。

原因：语义锚点、富文本粘贴和平台渲染可能产生偏差，必须保留人工式页面判断。

## ADR-004 使用专业技术长文默认样式

状态：已确认

决定：使用克制的深蓝技术长文样式；当篇排版指令优先覆盖默认值。

## ADR-005 原创声明默认开启

状态：已确认

决定：默认勾选原创声明，其他发布设置沿用后台默认值。平台出现额外原创承诺或资格异常时由用户处理。

## ADR-006 发布必须获得当次确认

状态：已确认

决定：排版后保存草稿并停留在预览。仅当前文章、当前草稿、当前内容版本的明确确认可授权发布；确认后内容变化会使授权失效。

## ADR-007 仅由主 Agent 开发和验证

状态：已确认

决定：不使用子代理，所有设计、实现、离线测试和审查均由主 Agent 完成。

## ADR-008 测试夹具必须使用合成内容

状态：已确认并实施

决定：可交付 Skill 内只保留明确标注的合成测试文章。用户原稿只能从授权附件位置读取到临时运行目录，用于当次真实样例验收，不能进入 Git、Skill 归档或个人安装目录。

原因：真实文章属于请求输入，不是可长期复用的 Skill 资源。把它复制为单元测试夹具会混淆数据所有权和生命周期。
